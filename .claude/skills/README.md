# 本项目的 skills

改界面之前两份都要读。它们管的不是同一件事。

## `frontend-design/` —— 官方权威,管「怎么设计」

来源:[anthropics/skills](https://github.com/anthropics/skills/tree/main/skills/frontend-design)(Anthropic 官方,含 LICENSE)
下载日期:2026-08-28

通用方法论,不针对任何项目:

- 先出设计方案(配色 4-6 色 / 字体 2+ 角色 / 版式 / **signature 记忆点**),
  **再回头批判它是不是通用套路**,改完才允许写代码
- 点名了 AI 设计目前扎堆的三个默认长相,提醒别把自由度花在上面
- 「把大胆花在一个地方」:signature 元素是唯一的记忆点,其余保持安静
- 文案也是设计材料,不是装饰

⚠️ **它点名的默认套路 #1 是「暖奶油底 + 高对比衬线 + 赤陶色点缀」,
而本项目的 `--paper #fbf7ee` + Noto Serif 900 + `--accent #d6402b` 正中这一条。**
豁免依据是该 skill 自己写的:需求明确指定了视觉方向时,需求原话优先 ——
周令杰明确要漫画风,而漫画印刷本来就是新闻纸底 + 墨线 + 专色。
但这意味着**配色本身不构成差异化**,记忆点必须来自别处
(分镜排版、拟声词、书脊、欄外、动画番语汇)。

## `memoir-ui/` —— 本项目专用,管「这个项目具体怎么做」

不是通用规范,只服务 Memory Gallery:

- 设计命题:把平凡的日子变得不平凡
- 令牌表、既有语汇表(避免重造轮子)
- 材质隐喻与禁用清单
- 动效判据(2026-08-28 已按周令杰要求推翻「印刷品不会自己动」)
- 文案语气对照表、交付前自检清单

## 读的顺序

1. 先读 `frontend-design` —— 定方法:出方案 → 自我批判 → 再动手
2. 再读 `memoir-ui` —— 拿到这个项目的具体约束与既有语汇
3. 冲突时以 `memoir-ui` 为准(它记录的是周令杰对这个项目的具体决定)
